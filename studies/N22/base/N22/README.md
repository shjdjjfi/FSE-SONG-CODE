# N22: Data contracts across converging migration paths

**Status: executable public-case replication package; NOT a complete FSE Industry Track submission evaluation.**

This repository branch contains isolated N22 work. It leaves the repository's
N21 work on its separate branch untouched. The study asks when the same final
database schema and version ledger can conceal divergent application data.

## What was actually run

| Family | Project/revision | What was executed | Observed boundary |
| --- | --- | --- | --- |
| Typed payload | Open WebUI v0.9.6, commit 1a97751e | Real, unchanged Alembic migration body in SQLite/SQLAlchemy 2.0.48, versus a labelled community reference patch | Same schema/ledger, invalid Pydantic-typed JSON; 2+ existing users instead trigger a hard error |
| FK cascade | Drizzle ORM 0.44.7 | Real better-sqlite3 Drizzle migrator using a frozen issue-derived table-rebuild SQL template | Same schema/ledger, missing cascade children; SET NULL variant also preserves all row counts |
| Hook ordering | Django 5.1.8 + PetterS's issue repro | Real original Django migration commands on two separate SQLite instances | Direct migration errors; staging succeeds. This is **not** counted as a silent success |
| Legitimate data | Django 5.1.8 built-in sites | Fresh, staged, and user-customized real migrations | Schema/ledger same; user site customization is allowed |

Two independent real defect mechanisms come from documented issues. The inputs
are minimal, controlled databases, **not** historical production snapshots.
No company involvement, real customer count, or measured deployment impact is claimed.

## Result files

- `results/openwebui/openwebui-observations.json`: each original/patch run,
  SQLite DB, source hash, schema, ledger, row payload, Pydantic probe
- `results/drizzle/drizzle-observations.json`: each original/protected run,
  SQLite DB, child/attachment preservation, FK checks, and ledger
- `results/django/django-observations.json`: upstream issue reproduction,
  built-in sites negative controls, logs, and DB snapshots
- `results/evaluation.json`: a fully enumerated scoring matrix, baseline
  detections, descriptive rates and Wilson intervals
- `results/performance/performance.json`: synthetic SQLite query scaling,
  **not** industrial runtime or ROI

All source fixtures, observations, and SQLite databases use fictional records
such as example.com and test user ids.

The checked-in `artifacts/n22-results.zip` contains **all** recorded JSON
observations and SQLite snapshots. Individual `.sqlite` files are omitted
from GitHub's file tree to keep the checkout compact; they are reproducibly
regenerated by the replay command.

## One-command rerun (Linux)

Requirements: Python 3.12, Node.js 24, git, C++ build toolchain if
better-sqlite3 cannot use a prebuilt binary.

1. From repository root, install Python dependencies:
   `python -m pip install -r N22/requirements.txt`
2. Install pinned Node dependencies: `npm ci --prefix N22`
3. Run: `bash N22/scripts/replay.sh`

The script downloads two version-locked public upstream source checkouts under
`N22/_upstreams/`, reruns the experiments in **isolated local databases**,
then recomputes and verifies observations with four tests. Generated results
are deliberately overwritten on rerun. It never touches a production DB.

For independent verification, run the GitHub Actions workflow
`.github/workflows/n22-replay.yml` on the `n22-fse-industry` branch.

## Findings and limits

See [EXPERIMENT_REPORT.md](EXPERIMENT_REPORT.md) for the paper-ready empirical
summary, [SUBMISSION_GAPS.md](SUBMISSION_GAPS.md) for the open evidence gates,
and [PAPER_TABLES.tex](PAPER_TABLES.tex) for a concise LaTeX table.

Important: a generic method that tests correct domain-specific assertions
cannot, by itself, outperform an existing application test suite that checks
the same assertions. Here, the advantage is over *limited structural and
untyped data oracles* in an intentionally selected case set; no general
industrial gain, independent holdout recall, or statistical FPR bound is
established.
