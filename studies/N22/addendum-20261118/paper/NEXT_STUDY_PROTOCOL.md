# N22 后续正式实验协议草案（尚未执行 / NOT preregistered）

此文件用于分离**本次探索性复现**和**未来真正可用于验证 N22 方法工业价值的实验**。本文件不是注册记录，不能倒填“此前已冻结”。

1. **冻结方法。** 先确定合同定义/来源（维护者已有测试，或经工单核验的稳定业务查询），再定义路径采样算法、迁移 replay 成本单位、异常优先级和自动生成断言的程度。只在登记后用未见项目验证。
2. **预设样本框。** 自开源迁移事故和企业自愿数据中纳入一批独立项目；包括不同迁移系统、SQLite/PostgreSQL/MySQL、fresh、from-old-release、staged、rollback/reapply 等路径。公开筛选、排除和异常分类理由。
3. **保留原停止规则。** 两个及以上经独立维护者确认的真实缺陷；同等 replay/工程师时间预算、相对完整基线至少 **+15pp** recall；false-positive rate **≤5%**。如果真实比较不支持则停止/改题，不把结构基线重新命名为“完整基线”。
4. **公平强基线。** 使用项目原有 test suite、迁移测试助手、业务合同手工断言、Artemis 式 fresh-vs-upgrade 与 SQL 有意义差异校验；每条路径运行时间、准备时间和人工合同比较成本同样计入。
5. **盲测与独立标注。** 工单发布后由非方法实现者标注根因，冲突需裁定；将开发集和完全保留测试集分开。所有不确定支持政策的故障在未判定前标 conditional。
6. **统计单位。** 以独立项目/独立故障作为高层单元；每个项目的路径与随机种子作为重复测量。用分层 bootstrap 或聚类感知区间，不将 30 个用户字段值算作 30 个独立企业。
7. **工业价值。** 在 CI 或 staging 上记录工程师 triage 分钟、正确缺陷提前发现数、不可用数据风险、DB 容量/回放时间、回滚代价、误报修正成本，比较部署前后并保护敏感数据。
8. **复现实务。** 冻结容器镜像和完整依赖锁、数据库 seed 的生成算法、源码完整 SHA、独立 oracle、匿名化操作日志；确保原始文件、所有失败 run 和筛选顺序可以复算。
9. **提交门槛。** 只在更大样本下统计证据满足事先定下的目标，且工业实用性和先例差异清楚时，再以方法/效果论文投稿；否则转为经验/故障分类型短文，坦诚报告无增益结论。
